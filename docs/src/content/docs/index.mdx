## The problem

A typical app ends up with three different data layers — a REST client here, a GraphQL client there, raw WebSocket handling for realtime — each with its own error handling, its own mocking story, its own shape. Swap one backend and the business code that calls it has to change too.

<Tabs>
<TabItem label="Without nexdk">
```ts
// Three unrelated shapes, three unrelated error stories.
const res = await fetch(`/api/products?${qs}`)
if (!res.ok) throw new Error(`HTTP ${res.status}`)
const products = await res.json()

const { data, errors } = await graphqlClient.query({ query: PRODUCTS_QUERY })
if (errors) console.error(errors) // easy to silently swallow

const channel = supabase.channel('messages').on('postgres_changes', {}, handler).subscribe()
```
</TabItem>
<TabItem label="With nexdk">
```ts
// Same shape, same error contract, whatever the driver is.
await sdk.lomkit.products.get({ page: 1 })
await sdk.nhost.products.query({})
sdk.supabase.messages.subscribe({}, handler)
```
</TabItem>
</Tabs>

Business code declares **resources**; the protocol behind them (Laravel/Lomkit, Hasura, Supabase Realtime…) becomes an interchangeable detail. Swapping the backend never touches the business layer.

## Quickstart

```bash
npm install nexdk
# plus the driver(s) you need, e.g. @nexdk/driver-lomkit
```

```ts
import { createSdk, defineResource } from 'nexdk'
import { z } from 'zod'

const product = defineResource({
  name: 'products',
  schema: z.object({ id: z.number(), name: z.string(), price: z.number() }),
})

export const sdk = createSdk({
  drivers: { lomkit },
  resources: { lomkit: { products: product } },
})

const { data } = await sdk.lomkit.products.get({ page: 1 })
// data is typed as { id: number, name: string, price: number }[]
```

## What it doesn't do (on purpose)

`nexdk` is a **call grammar and driver contract**, not a cache. It doesn't dedupe in-flight requests, revalidate on focus, or keep a query cache — that's what [TanStack Query](https://tanstack.com/query) or [SWR](https://swr.vercel.app) are for, and they compose fine on top of a driver call. If your app needs that, pair the two; `nexdk` isn't trying to replace them.
